# 多平台发布文案：机制（平台集合、口吻、固定话题在各账号）

- 先读确认稿和最新封面再写。封面承担实物与数字反差，标题补观看价值与观众关系；**标题不承诺正文没回答的事**。没有封面的搜索/通知场景里标题自己要说得清主题。
- 每个平台一套：主推标题、备选标题、正文、适量话题、置顶评论。公众号加摘要；B 站 / YouTube 章节只用最终成片的实际时间点。用户只要部分平台就不扩全套。
- 正文从具体异常或观众熟悉的场景切入，再说为什么值得看；少堆"本期核对、拆解、讲清楚"式目录。
- 置顶评论 = 一句来源或口径说明 + 正片结尾那个问题，把免责和互动合成一条。评论邀请可回答的真实经验，不让观众选陌生术语。
- 不虚构热度、性能、收益、试用、个人经历。平台字段限制按当前入口核验，不把内部字数建议说成官方规定。
- 数字与本期来源文件一致；来源和核对日期留在正文尾或资料说明。
- 备稿不等于发布：本流程不发评论、不公开发布、不改账号设置。
- 小红书标题想多几个变体调 `dbs-xhs-title`，封面文案再打磨调 `mandy-xhs-cover-title`；平时不用。
